**Tree state:** all 5 test files pass, 60/60 assertions green (`npm test` → `ALL 5 TEST FILES PASSED`, exit 0). **Test-suite green is not evidence of correctness here** — most findings below are in behaviour the tests never exercise, and several directly contradict what a passing test appears to assert.

## 1. Summary verdict

# NO-GO

The candidate is **not fit to plan a physical Sefer Torah**, and several defects would cause silent, unrecoverable harm to a sofer's work on klaf. The test suite is green, but it is narrow and in places tests the wrong thing; independent probes falsify seven of the controller's previously-reported material issues that the correction wave claimed or appeared to fix.

**Blocking rationale (the five that alone force NO-GO):**

1. **Stretch can exceed the physical line.** `applyStretch` enforces per-letter caps but never the line's total remaining width. A probe applied 6.0 mm of stretch into a line with 1.0 mm leftover and was accepted, returning `leftover_mm: -5`. The sofer would be told to write a line that cannot fit on the klaf. (F-01)
2. **Known special passages silently become ordinary writing-ready lines.** With no pattern selected, Shiras Hayam / Ha'azinu / Vayehi Binso'a wrap through the normal fitter, produce zero blockers, and are exported as normal layout. `IMPLEMENTATION_BRIEF.md` and `PATTERN_REVIEW_CASES.md` both state absence of reviewed pattern metadata is a **blocker**, not permission for normal wrapping. The frontend even labels this state "normal wrapping (no pattern selected)" as a benign chip. (F-02)
3. **Progress carries onto text that changed.** `handleAdoptCandidate` trusts the client's `verified_unchanged_lines` with no server-side verification. A probe adopted a candidate declaring every line unchanged; line 1 kept status `written` while its text changed from `בראשית ברא אלהים` to `בראשית ברא`. This is exactly the "progress never silently moves to changed lines" guarantee, and it is absent. (F-03)
4. **Stretch/auto-suggest reflow against the live profile, not the snapshot.** `recomputeFullLines` reloads the current profile and geometry and re-runs `computeLayout`. After an unrelated profile edit, a stretch request on an existing draft returned **HTTP 500** (`baseline pitch 8mm is below letter height 9mm`) and leaked a stack trace to the server log. Where it does not crash, it silently edits a differently-reflowed line. (F-04)
5. **Verse search is broken and returns wrong answers.** The natural query `Genesis 1:4` returns 0 results; the bare query `1:4` returns **5 spurious matches** across different chapters via an `endsWith` fallback. Book refs are also polluted (`"Genesis 1-50 1:1"`). Requirement 12 ("jump to any posuk") is not met. (F-05)

Beyond these, the PDF export is structurally malformed, the frontend stretch UI uses a different measurement convention from the backend, the phone workflow is broken by a missing CSS class, and the qere/ketiv warning still asserts a normalization that was never performed (previously reported in `QERE_WARNING_RECHECK.md` and still unfixed).

**What is genuinely good and should not be regressed:** the frozen width fixture is exactly right (2.0 mm @ 3.0 mm ref → 3.0 mm @ 4.5 mm; +0.2 → 3.2; +0.3 → 3.3, scale unchanged); stroke is added exactly once; the למשפחותיכם×3 threshold correctly includes 2 inter-word gaps; klaf length is summed sheet **widths** with both partial-final conventions; Shem coverage now includes יה / אהיה / אלוה / suffixed and doubly-prefixed forms with an honest certain/uncertain split and source-annotation overrides; `computeLayoutAsync` **really does** yield the event loop via `setImmediate` (health served in ≤19 ms during an 856 ms 78k-letter compute); inline פ/ס markers now stay between words; duplicate stretch decisions aggregate before cap checking and leftover recomputes idempotently from the immutable base; Host/Origin/token/content-type/body-limit security is solid and well tested.

## 4. Test gaps

The suite is 60 green assertions across 5 files. It is well-built for what it covers (real HTTP boundary tests, restart survival, atomicity), but it has systematic blind spots — every CRITICAL finding above lives in one.

**Gaps that let a CRITICAL defect pass:**

1. **No total-geometry stretch test.** Every stretch test uses a single letter or a cap violation. Nothing sums multiple in-cap decisions against the line's leftover. → F-01. Add: sum-exceeds-leftover rejected; sum-equals-leftover accepted; post-stretch line still passes `validateLine`.
2. **No test for a known special passage with no pattern selected.** `layout.test.js:300-330` covers the *selected* pattern path and the unsupported-token path, never the "known range, nothing selected" path that silently wraps. → F-02.
3. **No adversarial adoption test.** `diff.test.js:55-71` passes a genuinely-first line id as verified and checks that *others* reset. It never asserts that a **changed** line declared verified is refused. → F-03.
4. **No test that stretch survives a live profile change.** `persistence.test.js:78-96` proves stored lines are immune to a profile change, but never issues a *stretch* after one — which is where the 500 happens. → F-04.
5. **No search test at all.** `engine/search.js` has zero coverage. No exact-ref test, no gematria test, no multi-line-verse test, and critically no **negative** test proving `1:4` does not match `5:4`. → F-05.
6. **No pattern-order test.** The pattern tests use tokens already in source order, so the `findIndex` reordering hole is invisible. Add a reversed-token pattern asserting rejection. → F-06.
7. **No pattern-geometry test.** `layout.test.js:209-216` asserts only `lines.length`, `fixed_pattern` and `tokens.length` — never the width contribution of `gap_before_mm`, never that gap items are emitted, never that overrides survive. → F-07.
8. **The max-gap test only covers the explicit path.** `layout.test.js:290-295` passes `max_inter_word_gap_mm: 99`, which is the branch that *is* guarded. There is no default-path test, and no exact-equality test. → F-08.
9. **The setuma-edge test only covers trailing setuma.** `layout.test.js:91-98` uses `אבגדה {ס}`; the leading-setuma test (`257-267`) checks width only. → F-09.
10. **The diff test uses an identical profile for the "no change" case**, so a measurement-only change is never exercised. → F-21.

**Whole areas with no tests:**

- **Frontend: zero tests.** 3,000+ lines of `public/` have no unit, DOM or browser tests. F-10 (unit-convention mismatch), F-11 (font-flow tikkun), F-12 (client Shem reclassification), F-13 (phone CSS class) and F-33 (guard always unverifiable) are all trivially catchable with a DOM harness. This is the single largest gap.
- **Exports.** No test opens the PDF, checks its object structure, counts pages, or asserts Hebrew presence; none checks CSV row count against line count or JSON completeness. → F-17.
- **Performance/concurrency.** `layout.test.js:334-347` asserts the async callback *fires*, not that the loop *yields*. No test issues a concurrent request during a large compute, and none covers `/api/compare` or candidate creation at scale. → F-15, F-16.
- **Full-corpus.** Largest tested source is three verses. No builtin-import test, no whole-book timing, no memory/response-size assertion. → F-29.
- **Qere/ketiv working view.** The test asserts a warning *string* exists, never that the derived tokens match what the warning claims. → F-18.
- **Unusual-letter types.** Only `dotted` is tested; large/small/broken/suspended have no fixture at all. → F-26.
- **Locked-mutation matrix.** Only DELETE-profile is tested. No test for PUT-profile, geometry mutation, or progress/adopt on a locked layout via direct API. → F-23.
- **Amud-level progress aggregation.** `store.layoutProgress` is defined and never called by any handler or test.

**Recommended priority for the fix wave:** F-01, F-02, F-03, F-04, F-05 (blockers) → F-06, F-07, F-08, F-09 (engine correctness) → F-10, F-11, F-12, F-13 (frontend truthfulness) → F-17, F-18 (honest exports/labels) → the remainder. Every fix should land with the specific failing test named above, written **first** and confirmed red on the current tree.
